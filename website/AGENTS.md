# BERM Claim Protocol

## Canonical data files
- `data/causal-graph.json` — 35 semantic nodes, 74 edges, 11 UI groups. Source of truth for graph topology.
- `data/claims.json` — Claims, evidence relations, and epistemic assessments.
- `public/data/references_full.json` — Bibliography (1000+ entries). Pure reference, no interpretation.
- `lib/evidence.ts` (`FIELDSTATE_EVIDENCE`, bounded v2 records) and `lib/legacyEvidence.json` (legacy A–F catalogue) — the two other evidence registries; how they relate to `evidence_relations` and migrate into it: [`docs/evidence-registries.md`](../docs/evidence-registries.md).

## Adding a claim
1. Add to `data/claims.json` under `claims[]` with lifecycle `"draft"`.
2. ID format: `claim.<domain>.<slug>` — no mutable interpretation in the ID.
3. Target must reference an existing node, edge, or route in `causal-graph.json`.
4. Run `npm run registry:validate` to check integrity.

## Adding an evidence relation
1. Add to `data/claims.json` under `evidence_relations[]`.
2. `referenceId` must exist in `references_full.json`.
3. `claimId` must exist in `claims[]`.
4. `relation` is always curated — never inferred.

## Epistemic levels
`L` (theoretical premise), `L*` (testable candidate), `M` (mechanism), `C` (association), `M|C` (both), `E` (repeated finding). NOT a weak→strong scale. `E` does NOT mean "the full route is established."

## ClaimRef component
Use `<ClaimRef claimId="claim.xxx.yyy">content</ClaimRef>` in page components to anchor claims to content. The anchor index is generated by `scripts/build-anchor-index.mjs`.

## Adding a route (Phase 7)
1. Add to `data/claims.json` under `routes[]`.
2. ID format: `route.<slug>` (kebab-case).
3. `targetClaim` must exist in `claims[]`.
4. `routeClaims` and `routeEvidence` must reference existing claims/evidence relations.
5. `independenceGroup` groups routes that share no evidence — routes in different groups should be verifiably independent.
6. Set `independenceVerified: true` only after confirming no shared assumptions, datasets, or evidence with routes in other groups.
7. Run `npm run registry:validate` to check integrity.

## Coverage and independence analysis
- `lib/claims/index.ts` exports `getNodeCoverage()`, `getCoverageStats()`, `analyzeIndependence()`, `getIndependenceGroups()`.
- Coverage tracks which graph nodes have claims, evidence, and assessments.
- Independence analysis checks shared assumptions/datasets/claims/evidence between route pairs.

## Locale copy (`const COPY = { en, fi, ja, fr, ko }`)
- `pickCopy(COPY, locale)` (`lib/i18n.ts`) falls back to English **per key**: a key that is missing, `""` or `[]` in a locale resolves to the English value; arrays of equal length merge element-wise, nested objects per key. Untranslated content therefore renders in English, never as an empty element.
- Every new key still goes into `en` (complete) and ideally `fi`; stubs (`""` / `[] as never[]`) in ja/fr/ko are acceptable.
- Pages whose locale is under 90 % translated show `<TranslationNotice copy={COPY} locale={locale} />` (`components/TranslationNotice.tsx`) at the top of `<main>`. Add it to any new long-form page.
- `npm run i18n:coverage` prints per-page, per-locale coverage (`--strict` fails on blank English keys).

## Civilization tables
The numeric tables on `/civilization/*` (pathopolites index, EMF→political output, r/K, moral breadth, loyalty collapse, policy vulnerability, IQ shredder) are literals computed by `berm/berm/civilization/political_biology.py`. `python3 berm/export_civilization.py` regenerates `public/data/civilization_indices.json`, and `berm/tests/test_civilization_site_sync.py` fails if any page literal drifts from the computation — update the Python model first, then the page text, then rerun both.

## Quality gates
- `prebuild`: reference index → reference validation → registry validation → `tsc --noEmit` (type errors fail the build; `next.config.ts` no longer ignores them).
- `postbuild`: `scripts/check-rendered-html.mjs` scans every prerendered HTML file and fails on raw `[[ref:…]]` tokens, empty `<h2–h4>`/`<p>` elements, or empty `<a>` links.
- `npm run lint` must stay at 0 errors. `[[ref:id|label]]` tokens only render as links inside `<InlineReferenceText>`.
- Quick manual check against the dev server: `curl -s localhost:3001/ja/<route> | grep -oE '<(h[2-4]|p)( [^>]*)?></(h[2-4]|p)>' | wc -l` must be 0.

## Validation
`npm run registry:validate` runs 18 checks: node ID format, edge integrity, parent/child consistency, DAG acyclicity, UI group coverage, claim targets, dependency chains, evidence relation refs, assessment integrity, translations, root/terminal nodes, version format, route definitions, independence group consistency.
